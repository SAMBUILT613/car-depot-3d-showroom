# ENES V10 — Owner Website Content Studio

## Purpose

V10 adds an Owner-controlled CMS for approved public site content. It keeps the existing marketplace inventory and workflows in place and adds a versioned content document with separate draft and published states.

## What the Owner can manage

- Brand name, descriptor, tagline, primary/light/compact logo, favicon and social images.
- Homepage hero copy and background image, search labels/placeholders, search shortcuts, category cards, featured/latest headings, empty-state actions, review explanation, property-request and seller sections, and section visibility.
- Header navigation, mobile menu copy, sign-in/account labels, list CTA and search placeholder.
- Category/search page headings and descriptions.
- Footer description, link columns, copyright suffix and closing note.
- About, contact and property-services page introductions and content blocks.
- Default SEO title, description and social-sharing image.
- Owner-supplied text for Terms, Privacy and Safety pages. These legal fields start blank; the existing placeholder pages remain in place until the Owner supplies and publishes approved replacement wording.

The ENES V7 brand system remains protected in code: Manrope and the approved ENES palette are not exposed as arbitrary theme fields. This prevents casual edits from breaking the agreed identity. Only supplied brand assets can be uploaded; no logo or marketing imagery is generated by the application.

## Roles and publication

- `content:manage` permits an authorized administrator to edit and save private drafts and upload site assets.
- Only the configured Owner identity, resolved server-side from `ENES_OWNER_CLERK_ID`, can publish. The API independently enforces this with `requireOwner()`; hiding the button is not the security boundary.
- Public pages read only the `published` JSON document. They never read the draft.
- Saving uses optimistic version checks, revision snapshots and audit events. Publishing checks the exact draft version, records the publication and revalidates the root layout.
- The editor retains the latest eight revisions for convenient recovery. Database revision records are not automatically pruned by this page.

## Brand assets

Uploads accept JPEG, PNG and WebP, up to 8 MB and 40 megapixels. The server checks the detected file signature against the declared MIME type, checks dimensions, strips image metadata and writes a uniquely named object under `site-assets/` in `R2_PUBLIC_BUCKET_NAME`. That bucket must differ from the private/pending listing-media bucket (`R2_BUCKET_NAME`), and `R2_PUBLIC_URL` must be an HTTPS base URL.

SVG uploads are intentionally not accepted by this endpoint. Convert a supplied vector logo to a high-resolution PNG or WebP before upload. No existing listing media is copied into the brand-asset area.

## Install in the local project

1. Back up the project and run `node scripts/v6/backup-db.mjs`. It requires the private `DIRECT_URL`, uses the installed PostgreSQL 18 tools when available, validates the generated dump with `pg_restore --list`, and must finish successfully before any database migration.
2. Unzip this V10 patch at the project root, preserving the directory structure.
3. Run `npm run v10:verify`. It runs the V10-only static checks, regenerates Prisma Client, validates the schema and runs a non-incremental TypeScript check. It does not apply a database migration or deploy.
4. After source verification, apply the additive migration with `npx prisma migrate deploy` using the configured `DIRECT_URL` from the private environment. This migration only creates `SiteContent` and `SiteContentRevision`; it drops or alters no marketplace tables.
5. Run `npm run db:seed:rbac` to register the new `content:publish` system permission. It does not create an Owner identity or assign ownership to another administrator.
6. Run `npm run cf:build` to produce the local OpenNext/Cloudflare bundle. This is a build, not a deployment.
7. Sign in as the configured Owner and open `/admin/site-content`. Review, save a draft, inspect the draft preview, then publish when the content has been approved.

Do not paste secrets into chat or commit `.env.local`. Do not run `prisma db push` or use destructive reset commands.

## Important behavior and limits

- Public content changes only after an Owner publishes. A saved draft is private.
- The editor includes a live-updating homepage summary preview; the public rendering uses the published document. The preview panel is not a pixel-perfect iframe of the entire site.
- Uploaded assets are public objects by design. Do not upload identity documents or private listing photographs here.
- Unused immutable assets are not automatically deleted, preventing a logo replacement from breaking a published page or revision. Storage cleanup should be a deliberate future operation.
- This patch does not configure production Clerk keys, send email, configure a domain, deploy a Worker, enable payments, change DNS or alter legal wording.
